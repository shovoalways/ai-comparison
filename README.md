# AI Code Comparison: Body Target Calculator

A small experiment to compare how different AI coding models handle the **same web development task**.

For this comparison, I gave the exact same prompt to two different AI coding models and asked them to build a complete **Body Target Calculator** using only HTML, CSS, and vanilla JavaScript.

The goal was not to tell you which one is "better", but to give you the actual generated code so you can inspect, run, and compare both implementations yourself.

## The Challenge

The prompt asked the models to build a single-page **Body Target Calculator** with:

* Semantic HTML
* Accessible form labels and validation
* Responsive design
* Light and dark mode
* Vanilla JavaScript
* Pure calculation functions
* Mifflin-St Jeor BMR calculation
* Step-based activity multipliers
* TDEE and calorie targets
* Protein, fat, carbohydrate, and water targets
* Step target calculation
* Estimated weekly weight change
* CSS animations with reduced-motion support
* No frameworks
* No build tools
* No CDN dependencies

The complete prompt used for the comparison is included below so you can run the exact same test yourself.

## The Prompt

```text
Build a single-page "Body Target Calculator" as three files: index.html,
style.css, app.js. No frameworks, no build step, no CDN links. It must run
by opening index.html directly in a browser.

STRUCTURE
- index.html: semantic markup only. A <form> with proper <label for>
  bindings, a results <section> that starts hidden.
- style.css: plain CSS with custom properties in :root for colors,
  spacing and radii. No preprocessor syntax.
- app.js: vanilla ES modules-free script. Keep calculation functions pure
  and grouped at the top, DOM wiring at the bottom. No global leaks beyond
  one init call.

INPUTS (one card, "Your information")
- Weight (kg), number, 30-300
- Age, number, 14-90
- Sex, select: Male / Female
- Height (cm), number, 120-230
- Average daily steps, number, 0-40000, helper text:
  "Use your normal average, not your maximum."
- Goal, select: Fat loss + muscle preservation / Maintain / Lean muscle gain
- Submit button: "Calculate my targets"

VALIDATION
- Use native HTML5 constraints (required, min, max, step) plus a small JS
  pass that shows an inline error message under the offending field.
- Never show a result if any field is invalid.

CALCULATION (pure functions, each with a one-line comment explaining it)
- BMR: Mifflin-St Jeor
- Activity multiplier from daily steps, not a dropdown:
  <5000 = 1.2, 5000-7499 = 1.375, 7500-9999 = 1.5, 10000-12499 = 1.65,
  12500+ = 1.8
- TDEE = BMR * multiplier
- Calories: fat loss = TDEE - 20%, maintain = TDEE, lean gain = TDEE + 10%
- Protein: 1.8 g/kg for fat loss and lean gain, 1.4 g/kg for maintain
- Fat: 25% of calories / 9
- Carbs: remaining calories / 4
- Water: 35ml per kg, plus 350ml for each 5000 steps above 5000
- Step target: current steps + 15%, capped at 15000
- Weekly weight change from the calorie delta, 7700 kcal per kg

RESULTS
- Reveal the results section below the form, no page reload
- CSS grid of cards: Calories, Protein, Carbs, Fat, Water, Step target
- One summary line: estimated weekly change and a rough timeline
- Fade/slide in with a CSS transition, respect prefers-reduced-motion
- "Recalculate" button that scrolls back to the form

UI
- Clean light theme. Page background #F7F8FA, white cards, 16px radius,
  soft shadow, generous padding
- One accent color for the primary button and the big numbers only
- System font stack, large bold headings, muted gray helper text
- Mobile-first. Single column on phones, two-column input grid above 640px
- Visible focus rings, accessible contrast
- Dark mode via prefers-color-scheme, driven entirely by the CSS variables

OUTPUT
Give me the three complete files, nothing abbreviated.
```

No installation is required.

```bash
cd ai-comparison
```

Then open either implementation's `index.html` directly in your browser.

For example:

```text
Astra/index.html
claude/index.html
```

There is no:

* npm install
* build process
* framework
* CDN
* server requirement

Just open the HTML file and test it.

## What to Compare

When comparing the two implementations, don't only look at whether the calculator "works".

Look at the code quality too.

### HTML

* Semantic structure
* Label/input relationships
* Accessibility attributes
* Native form validation
* Error message handling
* Meaningful HTML elements
* Overall markup cleanliness

### CSS

* Responsive layout
* CSS architecture
* Custom properties
* Naming consistency
* Dark mode implementation
* Accessibility and focus states
* Mobile behavior
* Animation and reduced-motion handling
* Unnecessary or duplicated styles

### JavaScript

* Calculation accuracy
* Separation of pure functions and DOM logic
* Function naming
* Validation handling
* Error handling
* DOM manipulation
* Event handling
* Code duplication
* Global scope pollution
* Maintainability

### User Experience

Try the same inputs in both versions and compare:

* Validation behavior
* Error messages
* Result presentation
* Responsive behavior
* Keyboard navigation
* Dark mode
* Recalculation flow
* Animation
* Edge cases

## Why This Comparison?

AI coding tools are getting very good at generating working websites.

But "it works" is only one part of good software.

A useful comparison should also look at:

**Correctness → Accessibility → UX → Code quality → Maintainability → Edge cases**

That's what this experiment is designed to explore.
